## Perché i dati sono separati

Nella tabella `ordini` non c'è scritto il nome del cliente, ma solo `cliente_id`: un numero che **fa riferimento** alla colonna `id` di `clienti`. Così il nome è scritto una volta sola, in `clienti`.

- **chiave primaria** — `id`, identifica in modo unico una riga della sua tabella
- **chiave esterna** — `cliente_id` in `ordini`, "punta" a una riga di `clienti`

## INNER JOIN

`JOIN` rimette insieme le righe di due tabelle secondo una condizione (`ON`):

```sql
SELECT ordini.id, clienti.nome
FROM   ordini
JOIN   clienti ON clienti.id = ordini.cliente_id;
```

Per ogni riga di `ordini`, il database cerca in `clienti` la riga con `id` uguale a `cliente_id` e le affianca. Quando due colonne si chiamano uguale (`id`), le distingui col prefisso `tabella.colonna`.

::: exercise c7-join

## JOIN + WHERE + GROUP BY

Dopo il `JOIN` la query prosegue come sempre: puoi filtrare, raggruppare, ordinare.

```sql
SELECT   clienti.citta, count(*) AS ordini
FROM     ordini
JOIN     clienti ON clienti.id = ordini.cliente_id
GROUP BY clienti.citta;
```

## LEFT JOIN

`JOIN` tiene solo le righe che hanno una corrispondenza. `LEFT JOIN` tiene **tutte** le righe della prima tabella; dove non c'è corrispondenza, le colonne dell'altra tabella valgono `NULL`.

Serve per le domande "chi **non** ha…":

```sql
SELECT clienti.nome
FROM   clienti
LEFT JOIN ordini ON ordini.cliente_id = clienti.id
WHERE  ordini.id IS NULL;      -- nessun ordine trovato
```

::: exercise c7-left

::: tip Alias di tabella
Si può abbreviare il nome della tabella: `FROM ordini o JOIN clienti c ON c.id = o.cliente_id`. Più corto da scrivere nelle query con tanti join.
:::
